Glossary

Context engineering. Every lesson uses these terms exactly as defined here. Last updated with lesson 0001.

Context window
All the text a model can reference when generating a response, including the response itself; a "working memory" distinct from training data. Up to 1M tokens depending on the model. Context windows
Context
Whatever is in the window for a given model call. In an API request that is the system prompt, every message (including tool results, images, documents), your tool definitions, and the output generated. Context windows
Context engineering
The strategies for curating and maintaining the best set of tokens during LLM inference, including information beyond the prompt. It asks which context configuration most likely produces the behaviour you want. Anthropic
Prompt engineering
Writing and organising instructions, especially the system prompt. In this course it is one part of context engineering. Anthropic
Token
The unit the window is measured in. Capacity, cost and the "budget" are all counted in tokens. Context windows
Attention budget
The idea that the model has limited attention to spend and each new token depletes it; so context is "a finite resource with diminishing marginal returns". Anthropic
Context rot
Accuracy and recall degrade as token count grows. More context is not automatically better. Context windows
System prompt
Standing instructions sent with every request. Aim for the "right altitude": between brittle hardcoded logic and vague guidance. Anthropic
Tool definition
The name, description and input schema of a tool, sent in the request. It costs tokens on every call. Tool use
Tool result
What your application returns after executing a tool call, sent back in a tool_result block. It occupies the window like any other message. Tool use, Context windows
Message history
Prior user and assistant turns. In a standard API conversation previous turns are preserved completely and accumulate. Context windows
Retrieved documents / external data
Outside information brought into the window for the task, up front or at runtime. Anthropic
Just-in-time retrieval
Keep lightweight references (file paths, queries, links) and load the content with tools at runtime, instead of loading everything up front. A hybrid, with some data loaded up front, is also described. Anthropic
Memory
Information stored outside the window that persists across conversations and is read back on demand. With Anthropic's memory tool it is a directory of files your application stores and serves. Memory tool
Structured note-taking
The agent writes notes (to-do lists, a NOTES.md) to persistent memory outside the window and pulls them back later. Anthropic
Compaction
Summarising a conversation nearing the window limit so it can continue. Anthropic advises maximising recall first, then improving precision. Anthropic, Context windows
Tool result clearing
Removing old tool results from the context in agentic workflows; a light-touch form of compaction. Context windows, Anthropic
Sub-agent
A specialised agent that works in its own clean window and returns a condensed summary to a lead agent. Anthropic
Prompt caching
Reuse of previously processed prompt prefixes (tools, system, messages, in that order) to cut cost and latency. Cached prefixes still occupy the window. Prompt caching, Context windows

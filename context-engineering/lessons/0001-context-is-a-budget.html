Context is a budget

Lesson 1 · Context engineering · about 10 minutes

Today's win. Given any LLM request, you can sort what is in it into five buckets and say why the total, not just your prompt, decides how well the model does. This is the base for designing agents you ship yourself.

From prompts to context

You already write good prompts. Anthropic's applied AI team describes prompt engineering as writing and organising instructions, mostly the system prompt, and presents context engineering as its natural successor: strategies for curating and maintaining the best set of tokens during inference, including information that is not the prompt.[1] Agents make this matter, because they loop: each turn adds tool calls, tool results and history, so you must decide what stays in view.The article says curation happens each time content is passed to the model, so it is an ongoing, iterative job, not a one-off write-up.[1]

The window is a budget

The context window is everything the model can reference when it answers, including the answer itself: a working memory, not the training data.[2] A big window does not mean you should fill it. The docs say plainly that more context is not automatically better: as token count grows, accuracy and recall degrade, which they call context rot.[2] Anthropic's framing is that context is “a finite resource with diminishing marginal returns” and that each new token draws down an attention budget.[1]

Curating what's in context is just as important as how much space is available.
Paraphrased from the context windows docs.[2]

Five buckets

Everything in an API request counts toward the window: the system prompt, every message (including tool results, images and documents), your tool definitions, and the output.[2] Add memory read back from outside the window, and you get five buckets to design.

BucketWhat it isYour lever
System promptStanding instructions each requestRight altitude: not brittle, not vague[1]
ToolsNames, descriptions, schemas; they cost tokens on every call[4]Few, clear, non-overlapping[1]
Retrieved dataDocuments, files, search resultsLoad just in time via references[1]
MemoryNotes kept outside the window and read back on demand[3]What to write, when to read
HistoryEarlier turns and tool results; previous turns accumulate in full by default[2]Compact or clear when it grows[1]

Two of these deserve a first look because they are the ones prompt writers overlook. Tools: a common failure is a bloated tool set with ambiguous choices; the post's test is that if a human cannot say which tool applies, an agent cannot be expected to.[1] Retrieval: instead of loading all data up front, an agent can keep lightweight references such as file paths or queries and load content with tools at runtime.[1] Anthropic's memory tool docs describe memory the same way: record what you learn in files and read them back on demand, which keeps the active context focused.[3]Compaction (summarising a conversation near the limit) and sub-agents come later; they are the history bucket's remedies. You will not be quizzed on them today.

Try it on your own work
